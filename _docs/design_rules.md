# 设计与维护规则

## 工作流程

- 项目服务于个人主页仓库的长期维护。
- 先阅读 `_docs/` 中相关文档，理解结构、规则与已有决策。
- 代码修改后执行与变更相称的轻量检查。
- 内容修改检查 HTML 结构、资源路径与链接目标。
- 布局修改检查桌面端及移动端显示。
- 更新相关文档，优先修订现有条目。
- Markdown 摘要文件保持在 250 行以内，采用简短条目。
- 交流与维护文档使用中文；现有主页内容为英文。

## 环境与文件

- 在 WSL 中使用 `leemzmz` 用户，不使用 root 操作项目。
- Python 命令使用 `python`，不使用 `python3`。
- 修改以下划线开头的目录须先获得用户批准；`_docs/` 除外。
- 核心功能代码源文件首字母大写。
- 脚本类代码源文件首字母小写。

## 代码约定

- 函数采用 camel 命名，动词在前。
- 成员变量使用 `m_` 前缀。
- 私有函数使用 `_` 前缀。
- 代码保护尽量放在公有函数中。
- 函数功能注释放在函数前。

## Projects 标签页维护

- 在 `index.html` 的 `[data-project-tabs]` 容器中增加直接子级 `article`。
- 每个项目需有全页唯一的 `id`，以及包含项目名称与链接的 `h3 a`。
- 项目介绍放在该 `article` 中；脚本自动从标题生成标签。
- 项目顺序即标签顺序，默认选中第一个项目。
- 保持 HTML 原始内容完整，确保脚本未加载时仍可阅读。
- 使用 tablist/tab/tabpanel 语义，选中标签为唯一标签键盘入口。
- 保留横向溢出、键盘焦点样式与打印时全部展开的行为。
